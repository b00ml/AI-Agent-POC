# M3 发票异常 AI 复核（业务环节 Skill）

本 Skill 是财务系统中「发票异常 AI 复核」环节的执行规范。业务运行时：
点击「AI 复核异常」→ 系统加载本 Skill 内容注入 DeepSeek 提示词 → 大模型按下列
工作流对每一条异常独立复核 → 输出结构化结论。

## 环节输入

- 待复核异常：规则引擎筛出的每一条异常（异常类型、发票信息、判断依据 basis）；
- 制度知识库条款：按异常类型检索到的条款（带文档出处，如《发票合规指引》）；
- 公司基准：公司全称「启衡精密制造有限公司」、税号 `91320594MA1TXXXX7Q`。

## 执行流程

1. 逐条独立复核，不依赖规则引擎的初判结论，只依据票面字段与制度条款；
2. 对每条异常给出唯一判定：`CONFIRM`（异常成立）/ `DOUBT`（证据不足或存在合理
   解释，需人工复核）/ `FALSE_ALARM`（规则误报，实际合规）；
3. 每条附 1-2 条理由（引用票面字段与条款）和置信度 0~1。

## 判断要点

- 税率：住宿 6%、旅客运输（铁路/航空）9%、出租车客运 3%、增值税专票 13%、
  普通服务票 6%；办公采购开具 13% 普票制度合法，不能仅凭票种认定税率异常；
- 抬头：必须为公司全称，简称/分公司/错字均不符；公司没有分公司
  （「启衡精密制造(苏州)有限公司」「苏州启衡精密制造有限公司」均属错误）；
- 税号：纳税人识别号必须为 `91320594MA1TXXXX7Q`（X 为脱敏位，按骨架比对）；
- 重复报销：同一发票代码+号码出现 2 次以上即重复，不因时间跨度/报销人豁免；
- 疑似重复/连号：同号不同码、同代码 ≥3 连号属「疑似」，能确认同一供应商
  同批次连开可判 FALSE_ALARM，否则按 DOUBT 保留人工复核；
- 供应商重复档案：同税号下多个不同名称 → 异常成立。

## 护栏

- AI 只给意见，不修改规则判定与单据状态；
- 禁止臆断：只依据提供的票面字段与制度条款，缺证据判 DOUBT；
- 宁可多标存疑，不放走确有问题的异常（漏判比误判成本更高）。

## 输出契约

严格只输出一个 JSON 对象：

```json
{
  "verdict": "CONFIRM | DOUBT | FALSE_ALARM",
  "reasons": ["1-2 条判断理由"],
  "confidence": 0.0 到 1.0
}
```

## 边界

- API 失败/输出结构非法：记 error，按规则结论降级，不阻塞整批；
- 知识库未命中条款：明确标注「未检索到相关条款」，仍按核心口径判定；
- 字段缺失：不臆断，按 DOUBT 提请人工。

## 测试

运行 `scripts/test_m3_ai_review.py` 验证本 Skill：3 条测试覆盖
正常流程（违规成立→CONFIRM）/ 失败场景（规则误报→DOUBT/FALSE_ALARM）/
边界场景（非法输出拦截 + 字段缺失降级 DOUBT）。
